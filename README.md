# astrbot_plugin_reply_merge（思维链式消息防抖）

像 agent 一样"先想再回"：消息触发 LLM 后不立即回复，而是进入一个**思考驱动的滑动合并窗口**。等待期间由 LLM 思维链真正思考用户已发来的消息——判断用户想说什么、是否已经说完——并据此决定再等多久；窗口期内同一用户连发的文字和表情包都会并入同一次请求，机器人只回复一条，并且是对全部内容的统一理解。

## 工作方式

1. 第一条触发 LLM 的消息成为"领队"，开启合并窗口（按"会话+发送者"隔离）
2. 领队立即做第一轮**内心思考**：分析用户这条消息，输出"用户想表达什么 + 建议再安静等几秒"（说完给 3~8 秒，明显没说完给 15~25 秒）
3. 窗口期内该用户每发一条新消息：内容并入领队请求，领队被唤醒，短暂沉淀约 1 秒（吸收瞬时连发）后再思考一轮——每轮都能看到上一轮思考，形成真正的思维链
4. 思考给出的等待时长钳制在 `min_wait`~`max_wait` 内；从第一条消息起窗口最多存活 `max_window` 秒（默认 60 秒），防止一直发消息导致一直不回复
5. 安静期满，最后一轮思考以"内心思考"块注入提示词（模型不会复述它），后继消息以标记块拼进提示词，图片按需附加，模型统一理解后回复一次
6. 思考失败（模型不可用、返回解析不出）或关闭思考开关时，自动退回 v1 行为：纯随机安静期的滑动合并

## 配置项

| 配置 | 默认 | 说明 |
| --- | --- | --- |
| enable_thinking | true | 启用思维链思考；关闭则退回纯随机防抖 |
| think_provider_id | （空） | 思考所用模型 ID，留空用会话当前模型；建议填个更快更便宜的小模型 |
| min_wait / max_wait | 5 / 15 | 思考等待时长的钳制范围，也是兜底随机安静期范围（秒） |
| max_window | 60 | 窗口总时长上限（秒） |
| max_followups | 10 | 最多合并条数，超出以省略标记带过 |
| forward_images | true | 是否把窗口期内的图片一并交给模型 |

## 查看思维链

- **实时**：每轮思考都会打进 AstrBot 日志（WebUI 日志页可看），格式如 `[merge] thought pass 2 (wait 12s, 1 follow-ups): 用户在问今天下午的安排…`
- **聊天里查**：发送命令 `/思维链`（别名 `/thoughts`、`/思考链`），机器人会回出最近一轮完整思考链：合并了哪些消息、每轮想了什么、各轮判定的等待秒数
- 思考失败的轮次会如实显示"（思考失败，退回随机等待Ns）"

## 注意

- 每个窗口最多思考 10 轮（内置上限），连续刷屏的后半段退回随机等待，控制成本
- 不同用户互不影响（按"会话+发送者"开窗口）
- 群聊中只有 @机器人 或以唤醒前缀开头的消息才参与合并与回复，普通群消息不触发
- 窗口期内发送的命令会被当作普通消息合并掉，请等回复后再发命令
- 纯文本模型收不到图片内容，只会看到 `[图片/表情包]` 占位标记
