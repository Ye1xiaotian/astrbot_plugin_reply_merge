# 思维链式消息防抖（astrbot_plugin_reply_merge）

让 Bot 不再"收到一句回一句"：消息触发 LLM 后，由一段**真正的思维链**判断用户是否说完、决定何时回复；等待窗口内同一用户连发的文字与表情包会合并进同一次请求，机器人只回一条，且这条回复建立在对全部内容的统一理解之上。

## 它解决什么问题

- **碎句连发被逐句抢答**：用户习惯把一句话拆成几条发（"那个"→"今天下午"→"出去吃饭吗"），普通机器人每条都触发一次回复，答非所问。
- **定时防抖不智能**：固定延迟的防抖要么让完整提问也傻等满额时间，要么用户话没说完就抢先回复。
- **黑盒等待**：机器人"为什么现在才回/为什么这么回"无从知晓——本插件的思考过程全程可查（日志 + `/思维链` 命令）。

## 工作方式

1. 第一条触发 LLM 的消息成为"领队"，开启合并窗口（按"会话+发送者"隔离）
2. 领队立即做第一轮**结构化内心思考**，输出：对用户每条消息的**逐条要点**、**总体判断**（用户想做什么、说完没有）、**未解决的问题**，以及动作决策 **reply（现在就回）或 wait（再等 N 秒）**——思考时会被告知窗口状态（已等多久、距强制收尾还剩多少、已收几条）
3. 判定 **reply**：跳过安静期下限，仅保留约 2 秒拟人间隔即回复（完整提问不再傻等）；判定 **wait**：按建议秒数等待（钳制在 `min_wait`~`max_wait`），明显没说完时模型会给到上限
4. 窗口期内该用户每发一条新消息：内容并入领队请求，领队被唤醒，短暂沉淀约 1 秒后再思考一轮——每轮都能看到上一轮的**完整结构化思考**，形成低信息损失的推理链
5. 安静期满（或模型下令回复）后，最后一轮结构化思考整份注入提示词（标记"内心思考，不要复述"），后继消息以标记块拼进提示词，图片按需附加，模型统一理解后回复一次
6. 每轮思考在日志中记录**模型请求的等待**与**实际生效的等待**，调度行为可从日志统计；思考失败（模型不可用、解析不出）或关闭开关时，自动退回纯随机安静期的滑动防抖，功能不中断

## 指令

| 指令 | 别名 | 说明 |
| --- | --- | --- |
| `/思维链` | `thoughts`、`思考链` | 查看当前会话最近一轮完整思考链：合并了哪些消息、每轮想了什么、动作与各轮判定的等待秒数 |

指令前缀跟随你在 AstrBot 中配置的唤醒前缀（默认 `/`）：若你把唤醒前缀改成了别的（如「大肥鱼」），请相应写作 `大肥鱼思维链`；群聊中 @机器人 后直接发 `思维链` 也可以。

## 查看思维链

- **实时**：每轮思考都会打进 AstrBot 日志（WebUI 日志页可看），格式如 `[merge] thought pass 2: action=wait requested=15s effective=15s | 用户在列举，还没说完`，`requested`/`effective` 分别是模型请求的与钳制后生效的等待
- **聊天里查**：发送 `/思维链`（前缀跟随你的唤醒前缀配置），机器人直接回出最近一轮思考链
- 思考失败的轮次会如实显示"（思考失败，退回随机等待Ns）"

`/思维链` 输出示例：

```
🧠 最近一轮思考（10-20 21:14，共3轮）
📩 那个 / 今天下午 / 出去吃饭吗
1. [wait·等12秒] 用户话说一半，可能继续
   · 只说了个开头
   ❓ 想做什么事
2. [wait·等15秒] 在补充时间信息，仍在列举
   · 说的是今天下午
   · 时间未定
3. [reply·等2秒] 问完了：约今天下午吃饭
   · 想约今天下午
   · 对象是"出去吃饭"
   ❓ 几点出发、去哪家
```

## 配置项

| 配置 | 默认 | 说明 |
| --- | --- | --- |
| enable_thinking | true | 启用思维链思考；关闭则退回纯随机防抖 |
| think_provider_id | （空） | 思考所用模型 ID，留空用会话当前模型；建议填个更快更便宜的小模型 |
| min_wait / max_wait | 5 / 15 | wait 判定的等待钳制范围，也是兜底随机安静期范围（秒）；reply 判定跳过下限，仅保留约 2 秒拟人间隔 |
| max_window | 60 | 窗口总时长上限（秒） |
| max_followups | 10 | 最多合并条数，超出以省略标记带过 |
| forward_images | true | 是否把窗口期内的图片一并交给模型 |

## 安装

- **WebUI 安装**：管理面板 → 插件市场 → 从 URL 安装，填 `https://github.com/Ye1xiaotian/astrbot_plugin_reply_merge`
- 安装或更新后**重载插件**生效
- 思考调用与正式回复走同一套 Provider：不单独配置 `think_provider_id` 时使用会话当前模型；追求更快更省可填一个便宜小模型的 Provider ID

## 注意事项

- 每个窗口最多思考 10 轮（内置上限），连续刷屏的后半段退回随机等待，控制成本
- 不同用户互不影响（按"会话+发送者"开窗口）
- 群聊中只有 @机器人 或以唤醒前缀开头的消息才参与合并与回复，普通群消息不触发
- 窗口期内发送的命令会被当作普通消息合并掉，请等回复后再发命令
- 纯文本模型收不到图片内容，只会看到 `[图片/表情包]` 占位标记

## 适配说明

- 适配 AstrBot v4.x（依赖 `on_llm_request` 钩子与 Provider `text_chat` 接口）
- 平台无关：aiocqhttp（QQ/NapCat）、微信等全平台消息源均可使用
